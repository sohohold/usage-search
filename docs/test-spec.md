# テスト仕様書（青空用例検索）

このアプリケーションの振る舞いを定めた仕様書です。**この表が仕様の一次資料**であり、
`tests/` 以下のテストは表の1行＝1テストケースとして対応します。実装がこの表と食い違う場合、
原則として直すのは実装側です。

仕様を変えるときは、まずこの表を書き換え、それからテストと実装を直します。

## 読み方

- 各行の ID（`AZ-02`、`API-09` など）はテスト名の先頭に入っています。失敗したテストの名前から、
  該当する仕様の行を直接引けます。
- ID はモジュールごとに連番です。節をまたぐところで番号が飛びますが、欠番に意味はありません。

| 接頭辞 | 対象 |
|---|---|
| `AZ` | `scripts/aozora.ts` — 本文の整形 |
| `CH` | `scripts/aozora.ts` — チャンク分割 |
| `IX` | `scripts/catalog.ts` — 目録の解析とインデクサの補助関数 |
| `DB` | `lib/db.ts` — 検索クエリと統計 |
| `API` | `app/api/*/route.ts` — Route Handler |
| `UI` | `components/*.tsx` — 表示コンポーネント |
| `PG` | `app/page.tsx` — 検索フロー |

## 1. テストの構成

| 項目 | 内容 |
|---|---|
| ランナー | Vitest（`npm test` / `npm run test:watch` / `npm run test:coverage`） |
| 実行環境 | 既定は `node`。DOM が必要なファイルだけ先頭の `// @vitest-environment jsdom` で切り替える |
| DOM テスト | `@testing-library/react` + `@testing-library/jest-dom`。操作は `@testing-library/user-event`、ただし `app/page.tsx` はフェイクタイマーと併用するため `fireEvent` を使う |
| DB テスト | モックせず、一時ファイル上に本物の SQLite + FTS5(trigram) を作って検証する。`snippet()` や `MATCH` の挙動自体が検証対象のため |
| API テスト | Route Handler を直接 `import` し、`NextRequest` を渡して `Response` を検証する（サーバー起動は不要） |
| 配置 | `tests/` 以下にソース構成をミラーする。共有フィクスチャは `tests/fixtures/`、DB の種データは `tests/helpers/` |
| CI | `.github/workflows/ci.yml` で型チェック・`npm test`・本番ビルドを実行。別ジョブで50作品分の実インデックスを構築し、索引内容と API 応答を確認する |

インデクサ本体（`scripts/build-index.ts`）は import しただけで `main()` が走るため、テスト対象の
純粋関数は `scripts/catalog.ts` に分離してあります。

## 2. `scripts/aozora.ts` — `cleanAozoraText`

青空文庫の生テキスト（Shift_JIS からデコード済み）から、検索対象にすべき本文だけを取り出します。

出力は「空行で区切られた段落の並び」で、各段落は1行に収まります。段落の内側にあった改行は
区切り記号 ` / `（`LINE_JOINER`）に置き換えられます。検索結果はチャンク単位でカード1枚に
表示されるため、チャンクの中に改行が残っていると表示が崩れるためです。

| ID | 観点 | 入力 | 期待する挙動 |
|---|---|---|---|
| AZ-01 | ヘッダ除去 | 先頭に「題名／著者名／空行／罫線」 | 罫線より前のメタ情報が本文に残らない |
| AZ-02 | 記号説明ブロック除去 | 罫線が2本あり、間に `【テキスト中に現れる記号について】` がある標準形式 | 2本目の罫線までを削除し、説明ブロックも2本目の罫線自体も本文に残らない |
| AZ-03 | 説明ブロックなし | 罫線が1本だけ（説明ブロックを持たない作品） | 1本目の罫線までを削除する |
| AZ-04 | 罫線なし | 罫線を含まないテキスト | 全文をそのまま本文として扱う（誤って削らない） |
| AZ-05 | フッタ除去 | 本文の後に `\n底本：…` | `底本：` 以降の書誌情報を落とす |
| AZ-06 | フッタ除去（半角コロン） | `\n底本:…` | 同上 |
| AZ-07 | フッタなし | `底本` を含まないテキスト | 末尾を削らない |
| AZ-08 | ルビ除去（縦棒あり） | `｜東京《とうきょう》` | `東京` になる |
| AZ-09 | ルビ除去（縦棒なし） | `漢字《かんじ》` | `漢字` になる |
| AZ-10 | ルビ除去（半角縦棒） | `\|東京《とうきょう》` | `東京` になる |
| AZ-11 | ルビ記号の残留なし | ルビを含む本文 | 出力に `《` `》` `｜` が残らない |
| AZ-12 | 改行をまたぐ `《》` | `《` と `》` が別の行にある | ルビとみなさず削除しない（誤爆防止） |
| AZ-13 | 入力者注の除去（全角） | `［＃「一」は中見出し］` | 削除される |
| AZ-14 | 外字注記の除去（全角） | `※［＃「てへん＋劣」、第3水準1-84-77］` | 削除される（`※` も残さない） |
| AZ-15 | 入力者注の除去（半角） | `[#…]` / `※[#…]` | 削除される |
| AZ-16 | 注記の残留なし | 注記を多数含む本文 | 出力に `［＃` `］` が1つも残らない |
| AZ-17 | 段落内の改行 | CRLF / CR / LF が混在する複数行の段落 | すべての改行が ` / ` に置き換わり、段落が1行になる。各行の前後の空白は落とす |
| AZ-18 | 段落の区切り | 3行以上の連続空行、空白だけの行 | 空行は段落の区切りとして残り、連続分は空行1つにまとまる |
| AZ-19 | 前後の空白除去 | 先頭・末尾に空行や空白 | 取り除かれる |
| AZ-20 | 実データ結合テスト | 実作品のフィクスチャ（`tests/fixtures/kokoro-excerpt.txt`） | 本文の先頭が作品本文の1行目で始まり、`［＃` `《` `》` `底本` `入力：` と凡例ブロック・罫線を含まない。各段落に改行が残らない |

> **AZ-13 / AZ-14 について**: 青空文庫の実テキストは入力者注を**全角**の `［＃…］` で書きます。
> 半角の `[#…]` しか除去しないと、「中見出し」「傍点」といった注記の語が本文として索引され、
> 検索ノイズになります。

## 3. `scripts/aozora.ts` — `splitIntoChunks`

整形済み本文を、FTS インデックスの単位に分割します。1チャンクが検索結果カード1枚に対応します。

- `MIN_CHUNK_LENGTH` = 15 … これ未満の段落は文脈として役に立たないため索引しない
- `MAX_CHUNK_LENGTH` = 400 … カード1枚に収まる上限

| ID | 観点 | 入力 | 期待する挙動 |
|---|---|---|---|
| CH-01 | 段落分割 | 空行で区切られた複数段落 | 段落ごとに1チャンク |
| CH-02 | 短い段落の除外 | 15文字未満の段落 | チャンクに含めない |
| CH-03 | 境界値 | ちょうど14文字・15文字の段落 | 14は除外、15は採用 |
| CH-04 | 上限以下はそのまま | 400文字以下の段落 | 分割せず1チャンク |
| CH-05 | 長い段落の分割 | 400文字超・文末記号あり | `。！？」』` の直後で分割し、各チャンクが400文字以下になる |
| CH-06 | 分割の非破壊性 | 400文字超の段落で、末尾断片が15文字以上になるもの | 分割後のチャンクを連結すると元の段落と一致する（欠落も重複もない） |
| CH-07 | 末尾断片の扱い | 分割後の最後の断片が15文字未満 | 捨てる。この場合だけ CH-06 の一致は成り立たない |
| CH-08 | 文末記号なしの長文 | 400文字超で `。！？」』` を含まない | 400文字以下に強制分割する |
| CH-09 | 空入力 | `''` / 空白のみ | 空配列を返す |
| CH-10 | trim 済み | 各段落に前後の空白あり | 各チャンクの前後に空白が残らない |
| CH-11 | サロゲートペアの保護 | 上限での切れ目が補助面の文字（例: `𠮟`）の途中に落ちる段落 | ペアを分断せず切れ目を手前にずらす。孤立サロゲートを含むチャンクを作らない |
| CH-12 | 短い文で始まる長い段落 | 15文字未満の文の後ろに、それ以上分割できない長さが続く段落 | 単独では切り出せない先頭部分を後続と繋いだうえで上限以下に切る。上限超のチャンクを作らない |

## 6. Route Handlers

### 6.1 `app/api/search/route.ts`

`MIN_QUERY_LENGTH` = 3。trigram トークナイザーの制約上、2文字以下のクエリは原理的にマッチしません。

| ID | 観点 | リクエスト | 期待する挙動 |
|---|---|---|---|
| API-01 | q 未指定 | `/api/search` | 400 + `{error: "3文字以上入力してください"}`。検索は実行しない |
| API-02 | q が短い | `?q=ab` | 400。検索は実行しない |
| API-03 | 境界値 | `?q=abc`（3文字） | 200 |
| API-04 | 空白の扱い | `?q=%20あ%20`（trim 後1文字） | 400 |
| API-05 | 全角空白の trim | `?q=　東京の街　` | 全角空白を除いた `東京の街` で検索し、レスポンスの `query` も `東京の街` |
| API-06 | limit 既定値 | limit 未指定 | 20件で検索する |
| API-07 | limit 上限 | `?limit=100` | 50 に丸める |
| API-08 | limit 下限 | `?limit=0` / `?limit=-5` | 1 に丸める |
| API-09 | limit が非数値 | `?limit=abc` | 既定値 20 にフォールバックして 200 を返す |
| API-10 | offset が非数値 | `?offset=xyz` | 0 にフォールバックして 200 を返す |
| API-11 | offset が負 | `?offset=-5` | 0 に丸める |
| API-12 | キャッシュヘッダ | 成功時 | `Cache-Control: public, s-maxage=86400, stale-while-revalidate=604800` |
| API-13 | エラー時にキャッシュしない | 400 / 500 応答 | 上記のキャッシュヘッダを付けない |
| API-14 | DB 例外 | `search()` が throw | 500 + `{error: "検索中にエラーが発生しました"}` |
| API-15 | レスポンス形状 | 成功時 | `{query, over_limit, results[]}`、各要素が `{title, author, card_url, snippet, context}` |

> **API-09 / API-10**: 不正なクエリパラメータはサーバーエラーではないため、既定値へフォールバック
> します。`NaN` をそのまま渡すと SQL のバインド時に例外となり、500 として表面化します。

## 8. `app/page.tsx` — 検索フロー

`fetch` をスタブし、フェイクタイマーでデバウンスを制御して検証します。未解決のリクエストを
テスト側から任意の順に解決できるため、競合や中断の順序も再現できます。

デバウンスは 400ms（`DEBOUNCE_MS`）です。

| ID | 観点 | 操作 | 期待する挙動 |
|---|---|---|---|
| PG-01 | 統計の取得 | マウント | `/api/stats` を1回だけ呼び、作品数・段落数を表示する |
| PG-02 | 統計の失敗 | `/api/stats` が失敗 | 画面が壊れず、件数表示だけが出ない |
| PG-03 | 短い語の自動検索 | 2文字入力して 400ms 経過 | `/api/search` を呼ばない |
| PG-04 | 短い語の明示送信 | 2文字入力して検索ボタン | 送信し、サーバーが返した 400 のメッセージを表示する |
| PG-05 | 短い語の明示送信（Enter） | 2文字入力して Enter | 送信する |
| PG-06 | 空のクエリ | 空白のみ入力して Enter | 送信しない |
| PG-07 | デバウンス | 3文字入力 | 400ms 経過後に1回だけ `/api/search` を呼ぶ |
| PG-08 | デバウンスの再起動 | 300ms 間隔で連続入力 | 最後の入力から 400ms 後に、最後のクエリで1回だけ呼ぶ |
| PG-09 | 即時検索 | 検索ボタン | デバウンスを待たずに検索し、保留中のタイマーで二重に呼ばない |
| PG-10 | 先行リクエストの中断 | 検索中に新しいクエリ | 前のリクエストが abort される |
| PG-11 | 競合の解決 | 中断した先行リクエストが後から解決 | 古い結果で画面が上書きされない |
| PG-12 | 中断はエラーではない | 中断発生 | 「サーバーに接続できませんでした」を表示しない |
| PG-13 | 入力クリア | 3文字以上 → 2文字以下に戻す | 結果とエラーが消え、進行中のリクエストが abort される |
| PG-14 | 400 応答 | API が `{error}` で 400 | サーバーのエラーメッセージを表示する |
| PG-15 | 通信エラー | `fetch` が reject | 「サーバーに接続できませんでした」を表示する |
| PG-16 | エラーからの復帰 | エラー後に再検索が成功 | エラー表示が消える |
| PG-17 | もっと見る | ボタンをクリック | `offset` に既存件数を指定して呼び、結果を既存リストに追記する |
| PG-18 | 追記時のクエリ | もっと見る | 入力欄の現在値ではなく、表示中の結果の `query` で呼ぶ |
| PG-19 | 新検索中のページング抑止 | 新クエリの検索中に「もっと見る」 | ボタンが disabled で、追加リクエストを出さない |
| PG-20 | 結果なし時 | 未検索 | 「もっと見る」を表示しない |
| PG-21 | ローディング表示 | 検索中 | スピナーを表示し、既存結果を半透明にする。完了で元に戻す |
| PG-22 | 中断後のローディング表示 | 未解決のリクエストを新しい検索が追い越す | 中断された側の後始末が、実行中のリクエストのスピナーを消さない |
| PG-23 | 初期画面 | 未検索 | プレースホルダ（「青空文庫全文用例検索」）を表示する |
| PG-24 | アンマウント | デバウンス待ちのままアンマウント | タイマーが破棄され、検索が発火しない |

## 9. 対象外

| 項目 | 理由 |
|---|---|
| 実ネットワークへのダウンロード（`download` / `downloadCatalog`） | 外部依存。CI の50作品スモークテストで担保する |
| `snippet` の HTML エスケープ | `snippet` は `dangerouslySetInnerHTML` で描画するため、`<mark>` 以外のタグ文字はエスケープされない。青空文庫の本文に半角 `<` `&` が現れることは稀なため、現時点では対応しない |
| `app/layout.tsx` / Tailwind のスタイル | 見た目のみ。テストの費用対効果が低い |
| Vercel Analytics | 外部 SDK |
| 全件インデックスの性能・所要時間 | CI で回せない |
